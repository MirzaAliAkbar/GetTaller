# Production Readiness Fixes

## What Each Issue Is & Why It Matters

### 1. App Signing (Critical)

**What:** Android requires every APK/AAB to be digitally signed with a private key. Right now `android/app/build.gradle:36-37` has the signing config commented out — the release APK is either unsigned or using the debug key.

**Why it matters:** Google Play **rejects** APKs signed with the debug key. An unsigned APK can't be installed on any device. The signing key also serves as your identity — once published, all updates must use the same key.

**Fix:**
1. Generate a release keystore with `keytool`
2. Add a `signingConfigs` block in `android/app/build.gradle` referencing the keystore
3. Wire `signingConfig = signingConfigs.release` into the `release` buildType
4. Store the keystore password securely (not in git)

### 2. google-services.json Missing (Critical)

**What:** `lib/main.dart:17` calls `Firebase.initializeApp()` which needs `android/app/google-services.json` — a config file from the Firebase Console that tells your app which Firebase project to connect to. This file does not exist in the repo.

**Why it matters:** Without it, Firebase init will fail at runtime. Crashlytics won't work, and any future Firebase features (Analytics, Remote Config, etc.) will also fail. The current try/catch in main.dart masks this by printing a debug message and continuing.

**Fix:**
1. User must go to [Firebase Console](https://console.firebase.google.com), create a project (or use existing), add an Android app with package `com.gettaller.gettaller_app`
2. Download `google-services.json` and place it at `android/app/google-services.json`
3. This file is user-specific (tied to their Firebase project) so it stays out of git

### 3. ProGuard / R8 — Code Obfuscation (High)

**What:** R8 is Android's code shrinker/obfuscator. It removes unused code and renames classes to make the APK smaller and harder to reverse-engineer. Currently `android/app/build.gradle` has no `minifyEnabled` or `shrinkResources` — the release APK ships with all Flutter engine code, unused library code, and readable class/method names.

**Why it matters:**
- **Security:** Anyone can decompile your APK and read your logic, API calls, and hardcoded values
- **Size:** The APK is ~64MB; shrinking could reduce it significantly
- **Performance:** Fewer unused classes means faster startup

**Fix:**
1. Create `android/app/proguard-rules.pro` with keep rules for Flutter, Hive, Firebase, and AdMob (these libraries use reflection/serialization and break if obfuscated)
2. Add to `android/app/build.gradle` release block:
   ```
   minifyEnabled true
   shrinkResources true
   proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
   ```
3. Build with `--obfuscate --split-debug-info=build/debug-info` for Flutter-level obfuscation

### 4. No Analytics (High)

**What:** `firebase_analytics` is not in `pubspec.yaml` and zero analytics calls exist in the codebase. The app has zero visibility into user behavior.

**Why it matters:** Without analytics you can't know: how many users install, where they drop off in onboarding, which screens are most used, how many ads are viewed, what AI questions are asked, retention rates, crash-affected user counts, etc.

**Fix:**
1. Add `firebase_analytics: ^11.3.0` to `pubspec.yaml`
2. Create a thin analytics service wrapper in `lib/core/services/analytics_service.dart`
3. Add `logEvent` calls at key points:
   - Onboarding step completions
   - Screen views (via GoRouter observer)
   - Daily plan opened/completed
   - AI coach message sent
   - Ad impressions/clicks
   - Subscription events (if added later)

### 5. No CI/CD (Medium)

**What:** No automated pipeline exists. Every build, test, and deploy is manual.

**Why it matters:** Manual processes are error-prone and slow. No automated quality gates means broken code can ship.

**Fix:**
1. Create `.github/workflows/build.yml` with:
   - `flutter analyze` (static analysis)
   - `flutter test` (unit/widget tests)
   - `flutter build apk --release` (release build)
2. Optionally add Firebase App Distribution for beta testing

## Verification

1. **Signing:** Run `flutter build apk --release` and verify APK is signed with `apksigner verify --verbose app-release.apk`
2. **ProGuard:** Build release, verify APK size is smaller, try decompiling to verify obfuscation
3. **Analytics:** Run app, check Firebase Console > Analytics for incoming events
4. **CI:** Push to GitHub and verify the workflow runs green
