# Plan: Fix 5 Issues — Dashboard, Onboarding, Units, Navigation

## Issue 1: Exercise Cards → "Page not found"

**Root cause:** Dashboard navigates to `/workout/spine_1` which doesn't exist. The `/workout` route expects `extra` data (exercise IDs + level).

**Fix:** Change exercise card tap to navigate to Daily Plan tab instead.
- **File:** `lib/features/dashboard/presentation/screens/dashboard_tab.dart` line 365
- **Change:** `context.push('/workout/spine_1')` → navigate to `/main` with tab index 1 (Daily Plan)

## Issue 2: Unit Toggle — No Immediate Effect

**Root cause:** `persistedUserDataProvider` is a `FutureProvider` that fires once. Changing unit system in Settings doesn't invalidate it.

**Fix:** In `settings_screen.dart`, after saving unit system, invalidate `persistedUserDataProvider` and `heightMeasurementsProvider` so dashboard rebuilds.
- **File:** `lib/features/settings/presentation/screens/settings_screen.dart` `_saveUnitSystem()`

## Issue 3: Onboarding — Imperial Support & Scroll Pickers

### 3a: Save unit preference during onboarding
- **File:** `lib/features/onboarding/presentation/screens/current_measurements_screen.dart`
- When user submits, also call `UnitConverter.setMetric(_isMetric)` to persist the choice

### 3b: Parent height screen — add imperial support
- **File:** `lib/features/onboarding/presentation/screens/parent_height_screen.dart`
- Add unit toggle (read from `UnitConverter.isMetric`)
- Labels: "ft/in" when imperial, "cm" when metric
- Convert to cm on submit if imperial

### 3c: Replace TextField with scroll pickers for all number inputs
- **Files:** `current_measurements_screen.dart`, `parent_height_screen.dart`, `sleep_duration_screen.dart`
- Use `CupertinoPicker` or `ListWheelScrollView` (like birth_date_screen already does)
- Imperial height: two wheels (feet 4-7, inches 0-11), default to ~5'7"
- Metric height: one wheel (140-220 cm), default to ~170
- Weight: similar approach
- Parent heights: same scroll picker pattern

## Issue 4: Dashboard Shows Metric Even When Imperial Chosen

**Root cause:** Unit preference not saved during onboarding (Issue 3a fixes this).

**Fix:** After saving unit preference in onboarding (3a), UnitConverter reads it on next app launch. Dashboard already uses `UnitConverter.formatHeight()`.

## Issue 5: Back Button Doesn't Work in Onboarding

**Root cause:** Onboarding uses `context.go()` for forward navigation which replaces the route stack. `context.pop()` then has nothing to pop to.

**Fix:** Change `context.go()` to `context.push()` in onboarding screens so navigation stack is maintained. OR use `context.go('/onboarding/previous-step')` for explicit back navigation.

**Recommended:** Change forward navigation to `context.push()` in onboarding screens.
